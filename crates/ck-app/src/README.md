# ck-app/src — Application Use Cases

## Overview

`ck-app` is the application-layer crate of the Context Kernel workspace: it hosts `AppServices`, the use-case orchestrator that composes the `ck-core` ports (storage, session memory, artifacts, lexical search, ranking, source adapters, normalization, chunking, optional embedding/vector search) and implements the kernel's use cases — session context store/recall, source ingestion/refresh, reference query and resolution, retention GC, status aggregation, typed context resolution, and settlement-backed context-effect calibration. Persistence, search, and source fetching happen exclusively through injected ports; the single exception is `context_effect.rs`, whose `ContextEffectStore` writes an append-only JSONL ledger directly via `std::fs` inside this crate (known layering debt: a durable store living in the application layer instead of behind a port). The crate contains no transport (MCP/HTTP) code and no SQL; it re-exports its two submodules plus retention-classification helpers from the sibling `ck-memory` crate.

## Interface

- [lib.rs:AppServices] — public use-case orchestrator holding boxed `ck-core` ports (`StoragePort`, `SessionMemoryPort`, `ArtifactPort`, `LexicalSearchPort`, `RankerPort`, `SourceAdapter`, `Normalizer`, `Chunker`), optional `EmbeddingPort`/`VectorSearchPort`, kind-keyed additional source adapters, and an optional shared `ContextEffectStore` (calibration disabled when absent, never faked).
- [lib.rs:AppServices::new], [lib.rs:AppServices::with_semantic], [lib.rs:AppServices::with_source_adapter_kind], [lib.rs:AppServices::with_context_effect_store], [lib.rs:AppServices::semantic_available] — construction and builder surface.
- [lib.rs:RetentionPolicy], [lib.rs:RetentionGcReport], [lib.rs:AppServices::run_retention_gc] — time-cutoff garbage collection across session events, inactive sessions, finished refresh jobs, artifacts, disabled sources, and artifact payloads.
- [lib.rs:StoreContextRequest], [lib.rs:StoreContextResponse], [lib.rs:AppServices::store_context] — persist session text or artifact events and index them for search.
- [lib.rs:RecallContextRequest], [lib.rs:RecallContextResponse], [lib.rs:AppServices::recall_context] — lexical recall of session events scoped to all/current/recent, with ranker ordering.
- [lib.rs:IngestSourceRequest], [lib.rs:IngestSourceResponse], [lib.rs:AppServices::ingest_source] — snapshot ingestion: kind-selected adapter discover/fetch, normalize, chunk, replace documents and FTS index, record a completed `RefreshJob`.
- [lib.rs:QueryReferenceRequest], [lib.rs:QueryReferenceResponse], [lib.rs:AppServices::query_reference] — lexical plus optional semantic chunk retrieval with private-corpus gate, trust/freshness enrichment, ranking, excerpts, and citations.
- [lib.rs:ResolveReferenceRequest], [lib.rs:ResolveReferenceResponse], [lib.rs:AppServices::resolve_reference] — library-alias resolution with trust enrichment and optional `source_scope` filtering.
- [lib.rs:RefreshSourceRequest], [lib.rs:RefreshSourceResponse], [lib.rs:AppServices::refresh_source] — re-ingest an existing source from its stored adapter config.
- [lib.rs:AppServices::get_status] — aggregate a `KernelStatus` (source/session/job counters) from storage and session-memory ports.
- [lib.rs:pub use context::*, context_effect::*] — re-export of the context modules below; [lib.rs:pub use ck_memory::{classify_event_kind, EventRetentionClass, SessionRetentionPolicy as MemoryRetentionPolicy}] — retention helpers re-exported from `ck-memory`.
- [context.rs:ContextRequirement] and [context.rs:ContextRequirement::effective_result_cap] — typed, CEP-free input model for bounded retrieval (identity, pinned `world_ref`, query, mode, required concepts, corpora, scope constraints, freshness, budget, trace); effective cap = `max(max_results, 1)` clamped by a positive `budget.max_chunks`.
- [context.rs:RequirementIdentity], [context.rs:SourceConstraints], [context.rs:FreshnessRequirement], [context.rs:TraceRefs] — requirement sub-structures (caller scope/exclusions, freshness window, correlation/causation refs).
- [context.rs:ContextAccess] with [context.rs:ContextAccess::as_str] — data-access verdict: `Accessible`, `Inaccessible { corpus_id, reason }`, `RequiresScope { corpus_id }`.
- [context.rs:RetrievalOmission] with [context.rs:RetrievalOmission::code] / [context.rs:RetrievalOmission::with_detail], [context.rs:BudgetUsage], [context.rs:ContextResolution] with [context.rs:ContextResolution::has_context] / [context.rs:ContextResolution::blocked] — machine-readable resolution output model.
- [context.rs:AppServices::corpus] — corpus lookup for boundary adapters and auto-ingest paths.
- [context.rs:AppServices::resolve_context] — full retrieval pipeline: data-access gate, retrieval via `query_reference`, freshness gate, budget application, omission accounting, settlement-backed calibration, completeness verdict.
- [context.rs:AppServices::ingest_context_effects] — batch-append validated context effects to the ledger, returning [context_effect.rs:ContextEffectIngestReport].
- [context_effect.rs:ContextEffect] with [context_effect.rs:ContextEffect::validate] — durable settlement-backed calibration record (kind, pinned `world_ref`, bundle envelope/content hash, affected sources, required `evidence_ref`).
- [context_effect.rs:ContextEffectKind] — effect taxonomy (`RequiredDistinctionAbsent`, `SourceContradicted`, `SourceStale`, `DistinctionMaterialToSettlement`, `ContextItemUnused`, `ExcessiveRetrievalBurden`, `OmissionConsequential`).
- [context_effect.rs:ContextEffectError] — rejection reasons: `MissingEvidence`, `MalformedEvidenceRef`, `InvalidWorldRef`, `InvalidBundleHash`, `Io`.
- [context_effect.rs:CalibrationSummary] with [context_effect.rs:CalibrationSummary::penalty_for] / [context_effect.rs:CalibrationSummary::effect_count_for] / [context_effect.rs:CalibrationSummary::is_empty] — per-source demotion summary scoped to one world.
- [context_effect.rs:ContextEffectIngestReport] — accepted / skipped-duplicates / rejected batch outcome.
- [context_effect.rs:ContextEffectStore] with [context_effect.rs:ContextEffectStore::new] / [context_effect.rs:ContextEffectStore::path] / [context_effect.rs:ContextEffectStore::append] / [context_effect.rs:ContextEffectStore::load] / [context_effect.rs:ContextEffectStore::summary] — append-only JSONL ledger store for context effects.

## Invariants

- POL-ACL-002 private-corpus gate: a private corpus requires explicit caller scope; a missing or empty `source_scope` never grants access — `query_reference` errors with "unauthorized corpus" [lib.rs:AppServices::query_reference], and `resolve_context` blocks with `RequiresScope`/`Inaccessible` before any retrieval [context.rs:AppServices::resolve_context]. For whole-kernel searches the private-scope and exclusion rules are re-applied per result and fail closed [context.rs:AppServices::result_corpus_permitted].
- Never fabricate context: a blocked or empty retrieval returns `completeness == RetrievalCompleteness::None` with a machine-readable `NoContextReason` and omission; `no_context_reason` is set exactly when completeness is `None` [context.rs:AppServices::resolve_context], [context.rs:ContextResolution::blocked].
- Context access is data-access only and deliberately not an action-authorization verdict; SEA-Forge owns authorization of consequential actions [context.rs:ContextAccess].
- Snapshot-before-replace ingestion: the entire snapshot is discovered, fetched, normalized, and chunked before previous document rows and FTS entries are deleted, so an adapter/fetch failure leaves the old snapshot untouched [lib.rs:AppServices::ingest_source]. Re-ingestion must never open a private corpus: an existing corpus keeps its registered visibility [lib.rs:AppServices::ingest_source]. On failure the source is marked `Degraded` with the error; on success it is marked `Healthy` and a completed manual `RefreshJob` with docs/chunks stats is recorded [lib.rs:AppServices::ingest_source].
- `store_context` requires either text or artifact content and always ensures the session exists with `SessionTransport::Stdio` and `ContinuationMode::Ephemeral` [lib.rs:AppServices::store_context]; text above the 10 KB `LARGE_PAYLOAD_THRESHOLD` is diverted to an artifact with a 500-character summary [lib.rs:LARGE_PAYLOAD_THRESHOLD]; if the artifact row upsert fails, the stored artifact payload is deleted before returning the error [lib.rs:AppServices::store_context].
- Result caps: `top_k` is clamped to at least 1 and candidate pools are searched at `top_k * 3` then truncated to `top_k`, surfacing a `truncated` flag [lib.rs:AppServices::query_reference], [lib.rs:AppServices::recall_context].
- Freshness policy: score in [0.0, 1.0] with a 30-day default decay when no TTL is configured; malformed timestamps score 0.5, absent timestamps 0.0 [lib.rs:compute_freshness]. In freshness-gated retrieval, a result with no attributable source timestamp is never treated as stale (unknown is not converted into a verdict) [context.rs:AppServices::result_is_stale].
- Graceful degradation only, never faking: semantic search failure falls back to lexical-only with a warning [lib.rs:AppServices::query_reference]; calibration is disabled when no context-effect store is attached [lib.rs:AppServices] and an unreadable calibration summary proceeds uncalibrated with a warning [context.rs:AppServices::resolve_context].
- Settlement-backed calibration only: an effect requires an `evidence_ref` of the form `<kind>:<value>` with kind in {settlement, evidence, execution, observation, proof} (self-reports are rejected), a `world_ref` naming a pinned world revision, and a `bundle_content_hash` of `sha256:<64 lowercase hex>` [context_effect.rs:ContextEffect::validate].
- Ledger durability rules: append-only JSONL, one effect per line, idempotent by `effect_id` (duplicates skipped, records never rewritten) [context_effect.rs:ContextEffectStore::append]; an append onto a ledger that cannot be read must fail (no duplicate appends over an unreadable ledger) [context_effect.rs:ContextEffectStore::append]; loading is strict — one malformed line fails the whole read so a tampered ledger is never half-trusted [context_effect.rs:ContextEffectStore::load].
- Calibration is prospective and world-pinned: only settlement-established negative signals demote sources (`SourceContradicted` weight 0.20, `SourceStale` weight 0.10) [context_effect.rs:ContextEffectKind::demotion_weight]; penalties are capped at 0.5 [context_effect.rs:CalibrationSummary::penalty_for]; effects from other worlds never influence this world's retrieval [context_effect.rs:ContextEffectStore::summary]; `ingest_context_effects` is the only durable calibration path [context.rs:AppServices::ingest_context_effects].

## Side Effects

- Persistence and search exclusively through injected `ck-core` ports (`StoragePort`, `SessionMemoryPort`, `ArtifactPort`, `LexicalSearchPort`, `RankerPort`, `SourceAdapter`, `Normalizer`, `Chunker`, optional `EmbeddingPort`/`VectorSearchPort`); concrete backends are supplied by whoever constructs `AppServices` [lib.rs:AppServices].
- Filesystem I/O: `ContextEffectStore` reads and append-writes a JSONL ledger directly via `std::fs` (`create_dir_all` plus append-mode `OpenOptions`) [context_effect.rs:ContextEffectStore::append], [context_effect.rs:ContextEffectStore::load] — direct file access inside the application crate, bypassing a port (layering debt).
- Destructive deletes: retention GC deletes unpinned session events, inactive sessions, finished refresh jobs, artifact rows, disabled sources, and artifact payloads through ports [lib.rs:AppServices::run_retention_gc]; ingestion deletes previous documents and their FTS index entries before replacing them [lib.rs:AppServices::ingest_source].
- Time and identifiers: `Utc::now()` drives retention cutoffs, ingest timestamps, freshness scoring, and staleness checks [lib.rs:AppServices::run_retention_gc], [lib.rs:compute_freshness], [context.rs:AppServices::result_is_stale]; ULIDs are generated for query, artifact, and job identifiers [lib.rs:AppServices::store_context], [lib.rs:AppServices::ingest_source].
- Network-adjacent I/O behind ports: source adapters discover/fetch content and embedding/vector-search ports embed queries and search vectors; actual network traffic occurs inside the injected adapters, not in this crate [lib.rs:AppServices::ingest_source], [lib.rs:AppServices::query_reference].
- Logging: `tracing` info/warning events for retention GC completion, semantic-search fallback, unreadable calibration, and artifact payload deletion failures [lib.rs:AppServices::run_retention_gc], [lib.rs:AppServices::query_reference], [context.rs:AppServices::resolve_context].
